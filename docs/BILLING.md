# Поездки, тарифы и геозона

Реализовано по [U008](prompts/008-trip-lifecycle.md). Исходное предложение E0 о пропорциональной оплате заменено правилом ниже до реализации тарификации. Операции пока доступны через серверный API и CLI; продуктового UI поездки нет.

## Поминутное округление

Правило `ceil-per-mode-v1`: отдельно суммируем миллисекунды всех riding-интервалов и всех paused-интервалов. Каждую из двух сумм округляем вверх до целой минуты **один раз** за поездку. Нулевая длительность даёт ноль минут. Бронь, разблокировка и переключение режима бесплатны.

```text
activeMinutes = (activeMs + 59999) div 60000
pausedMinutes = (pausedMs + 59999) div 60000
totalMinor = activeMinutes × rideRateMinorPerMinute
           + pausedMinutes × pauseRateMinorPerMinute
```

Тарифы конфигурации: 800 тыйын/мин в движении и 200 тыйын/мин на паузе; 100 тыйын = 1 сом. Сервер использует TypeScript bigint, PostgreSQL bigint и целочисленные тарифы. API передаёт суммы, минуты и миллисекунды десятичными строками, чтобы не терять точность JSON/JavaScript number. Денежных float, toFixed и ежеминутных списаний нет. Превышение диапазона bigint не превращается в неверную сумму.

| Активное время | Паузы суммарно | Цена |
| --- | --- | --- |
| 0 ms | 0 ms | 0 тыйын |
| 1 ms или 60 s | 0 | 800 тыйын / 8 сом |
| 60001 ms | 0 | 1600 тыйын / 16 сом |
| 61 s | 10 s | 1800 тыйын / 18 сом |
| 30 s + 30 s | 10 s + 10 s | 1000 тыйын / 10 сом |

Последний пример демонстрирует, что разбиение riding или пауз на несколько интервалов не добавляет платных минут. Превью открытой поездки использует ту же формулу и DB-время; до закрытия оно растёт при пересечении следующих минут.

## Состояния и время

`reserved → riding → paused → riding`; завершение допустимо из riding и paused. Старт — только владельцем, до expires_at, с достаточным зарядом и operational-самокатом внутри зоны. На дедлайне старт запрещён и бронь закрывается как expired. Повтор pause в paused и resume в riding с новым ключом — конфликт; cancel после старта запрещён. Finish из finished с новым ключом возвращает тот же trip/invoice, без повторного расчёта или нового счёта.

Единое время операции берётся из PostgreSQL `clock_timestamp()` после ожидания locks и приводится к целым ms. Интервалы полуоткрытые `[started_at, ended_at)`, соседние границы совпадают; ordinal задаёт порядок и при нескольких переходах в одной ms. На каждом переходе закрывается один открытый интервал и открывается следующий. Разрыв/неверный порядок времён не допускается в расчёт. SQL UNIQUE запрещает второй открытый интервал; GiST EXCLUDE запрещает пересечения. Для него миграция включает стандартное расширение btree_gist.

Расчёт идёт по сохранённым интервалам, а не по памяти процесса, вкладке или количеству worker ticks. При потере связи riding или paused продолжается по серверному времени. После старого срока брони уже начатая поездка не истекает. При следующем чтении API восстанавливает длительности из PostgreSQL. Если серверные часы переведены назад, переход не записывает отрицательную длительность.

На старте в rental сохраняются тарифы, currency, billingPolicy и полный snapshot зоны. Их изменение в config не пересчитывает начатую поездку. Отмена/истечение брони счёта не создают.

## Геозона

`config/service-zone.json` — сохранённый целиком MultiPolygon OSM relation [8493930](https://www.openstreetmap.org/relation/8493930), полученный из Nominatim. Содержит четыре полигона, исходные кольца, source, retrievedAt, version и attribution ODbL. Порядок координат GeoJSON — **longitude, latitude**. Приложение работает офлайн со snapshot, не вызывает OSM при finish. Это карта OSM, не юридическое подтверждение актуальности административной границы; изменение зоны — отдельное конфигурационное решение.

Сервер проверяет сохранённые `vehicles.longitude_e7 / latitude_e7` под vehicle lock. Клиентские GPS, time, status и стоимость не принимаются командами. E7 и BigInt cross-products дают однозначную проверку рёбер/вершин без floating epsilon. Границы внешних колец и отверстий включены; внутренность отверстия и пространство между отдельными полигонами исключены.

Finish вне зоны возвращает `409 OUTSIDE_SERVICE_ZONE` с объяснением. Интервал остаётся открытым, состояние не меняется, счёт не создаётся; текущий режим продолжает тарифицироваться. После возврата в зону нужен новый idempotency key. Симулятор/GPS-телеметрия пока не реализованы: текущие координаты статичны; граничные координаты в integration tests меняются только в изолированной тестовой БД, а не доверенным клиентским запросом.

## Транзакции и оплата

Порядок locks: idempotency advisory → user → vehicle → rental → intervals → invoice. UNIQUE активных rentals покрывает reserved/riding/paused сразу и запрещает второму пользователю занять самокат в поездке. Finish закрывает интервал, завершает rental, создаёт единственный invoice и сохраняет idempotency result одной транзакцией. Ошибка вставки invoice откатывает всё.

Оплата **после** поездки отдельной командой `pay-demo`. Пустое тело или `outcome=approved` создаёт одну локальную demo-квитанцию и переводит invoice в paid атомарно; `outcome=declined` даёт 409 и оставляет unpaid. Ни банка, ни карты, ни внешнего запроса нет. Сервер берёт сумму из invoice. UNIQUE invoice_id запрещает второй платёж, FK сверяет сумму/валюту квитанции со счётом. Неоплаченный счёт пока не блокирует новую бронь: правило долга ранее не было согласовано.

Все write-команды требуют Bearer demo user и `Idempotency-Key: UUID`. Один key действует во всех командах одного пользователя: повтор с теми же нормализованными параметрами возвращает сохранённый результат, другая операция/параметры — 409 IDEMPOTENCY_CONFLICT. Сохранённый отказ также повторяется, даже если причина уже исчезла. Новый пользовательский шаг требует нового key. requestId ошибки относится к новому HTTP-запросу; это не часть сохранённого бизнес-результата. Replay start/finish может показывать исторический статус — для текущего состояния читайте GET. Платёж с новым ключом для paid invoice возвращает существующую квитанцию.

## API

| Маршрут | Ответ / назначение |
| --- | --- |
| GET `/api/v1/service-zone` | Публичный snapshot текущей конфигурации зоны |
| POST `/api/v1/trips/:id/start` | id действующей брони; пустое тело или `{}` |
| POST `/api/v1/trips/:id/pause` | Закрыть riding, открыть paused |
| POST `/api/v1/trips/:id/resume` | Закрыть paused, открыть riding |
| POST `/api/v1/trips/:id/finish` | Закрыть поездку и вернуть `{trip, invoice}` |
| GET `/api/v1/rentals/current` | `{serverTime, reservation, trip}`; только собственная текущая аренда |
| GET `/api/v1/trips/:id` | Собственная поездка и счёт, если он создан |
| GET `/api/v1/trips` | Последние 100 собственных завершённых поездок; cursor pagination пока нет |
| GET `/api/v1/invoices` | Последние 100 собственных счетов |
| POST `/api/v1/invoices/:id/pay-demo` | `{}` или `{outcome: "approved"/"declined"}`; `{invoice,payment}` |

Чужие trip/invoice возвращают 404 без данных владельца. Полноценная password/Google-авторизация остаётся открытой задачей. Email/outbox, автоматическое завершение при разряде, движение GPS, WebSocket и финальный UI в этот этап не входят.
