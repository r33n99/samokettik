## Ограничение по времени

Полные 15 минут реального ожидания в этой проверке не проходили. API создал бронь с исходными интервалами 900 секунд и предупреждением за 180 секунд, что проверено assertions. Затем только её timestamps сдвинуты под locks user → vehicle → rental, с сохранением интервалов 900/180; дедлайн назначен на DB now + 3 секунды. Бизнес-конфигурация и worker poll не менялись. Во время ожидания выполнялись только SELECT-запросы; HTTP lazy cleanup, ручной запуск jobs и отмена не могли выдать себя за автоматическое освобождение. Полный 15-минутный wall-clock сценарий остаётся отдельной непроведённой проверкой.

## Воспроизведение
