# Демонстрация для двух клиентов

Сценарий U021. Требуются установка по README и работающий PostgreSQL. Для демонстрации приложения — Compose; для автоматической проверки — npm ci/setup, собранные contracts и установленный Chromium. Не изменяйте main DB вручную ради таймеров/GPS/заряда.

## Автоматическая конкурентная проверка

Из корня:

```sh
npm run setup
npm run build -w @samokettik/contracts
npm run infra:up
npm exec -- playwright install chromium
npm run test:e2e -- --grep "two browser users compete"
```

Ожидается2 passed: desktop и mobile. Playwright сам создаёт отдельную UUID PG DB, API, worker и Vite (web5180 по умолчанию), затем удаляет собственную базу/процессы. Основные пользователи/аренды не отменяются. Если5180 занят, задайте E2E_WEB_PORT свободным портом. Нужны CREATEDB и системные зависимости Chromium. При ошибке — test-results/ и playwright-report/; traces могут содержать временные credentials, не публикуйте их без проверки.

В каждом тесте два независимых BrowserContext входят как Айжан и Бек, выбирают SK-005 и отправляют настоящие POST через сетевой barrier. Он задерживает отправку до готовности обоих, **не подменяет ответ API**. Проверяется ровно один201 и один409, countdown у победителя, понятная ошибка проигравшему, cancel победителя, обновление проигравшего и SQL count(active)=0. Исходник: tests/e2e/rental.spec.ts. PostgreSQL constraints/locks проверяются отдельно:

```sh
npm run test:db
```

## Ручной показ рабочего приложения

1. Запустите `npm run compose:up`, убедитесь в healthy API/worker и30 самокатах. Откройте http://localhost:5173/ в обычном и приватном окне либо в двух браузерах. Не дублируйте уже авторизованную вкладку как способ гарантировать независимые credentials.
2. В первом выберите Айжан, во втором Бек. Профили общие для демо, без паролей. Проверьте, что ни у кого нет активной брони/поездки. Если есть — её владелец отменяет/завершает сам; не очищайте базу и не отменяйте чужую активность скриптом.
3. Найдите SK-005 через «Самокаты · 30» или выберите один и тот же доступный транспорт. На чистом seed SK-005 имеет93%; SK-001/002 и maintenance демонстрируют недоступность. В существующей базе состояние может отличаться — выберите свободный с зарядом≥15%.
4. Нажмите бронирование в обоих окнах. Успех — один владелец; другой видит занятость либо409 с объяснением. Если WS успел отключить вторую кнопку до клика, это обычное поведение UI, а не доказательство simultaneous race: для точной гонки используйте автоматическую команду выше.
5. Владелец видит серверный15-минутный deadline. Второй клиент видит reserved. Просмотрите другой маркер: карта не уходит к своей аренде. «Показать свой самокат» явно возвращает к ней.
6. Владелец начинает поездку, ставит на паузу, продолжает. На обоих картах статус in_ride; в своём UI раздельно учитываются движение/пауза и приходит server cost. Ненулевая начатая минута каждого режима оплачивается отдельно: короткая поездка с короткой паузой обычно10сом, без паузы8сом; переход через60s меняет сумму по правилам, а не по числу кликов.
7. Закройте окно владельца либо включите offline в DevTools. Во втором клиенте/через API видно продолжение движения и расхода. Откройте владельца заново и выберите тот же профиль: активная поездка восстанавливается с сервера. Не ожидайте остановки тарификации из-за закрытия вкладки.
8. Завершите в геозоне с подтверждением. Проверьте одну завершённую поездку и один счёт, сверку суммы/времени и причину. В счетах сначала «Проверить отказ», затем успешная demo-оплата. Это заглушка, никаких реальных списаний. Истории доступны страницами20 записей, старые счета также можно оплатить.
9. `npm run mail:show` показывает локальные письма со счётом/причиной; повтор HTTP finish с тем же idempotency key не создаёт новое. Это PostgreSQL mailbox, не внешний email inbox. Для проверки exactly-one нужны тесты количества записей, а не только визуальное письмо.
10. Переключите RU/KY, уменьшите окно. Проверьте доступный список, labels, отсутствие переполнения и восстановление offline. Карта использует внешние OSM tiles; если они недоступны, список и серверные данные остаются.

## Длительность, геозона и полный разряд

В рабочей базе нет endpoints для ускорения часов, перемещения GPS или разряда. Не надо менять config или применять SQL к main, чтобы уложиться в показ.

```sh
npm run test:e2e -- --grep "server rejects finish outside|persistent warning|depletion updates"
npm run test:acceptance
```

Первая команда воспроизводит geofence/warning/expiry/depletion через trusted fixtures **только в UUID DB** и реальный worker. Проверяются запрет finish снаружи, освобождение брони, один invoice/notice/mail при разряде. Вторая ждёт реальные900s без fake clock: warning на12-й минуте, затем restart worker, expiry на15-й. U017 уже содержит такой фактически пройденный15-минутный тест; новые запуски журналируются отдельно.

## CLI-сценарии и последствия

```sh
npm run demo:reservations
npm run demo:trips
npm run demo:realtime
npm run mail:show
```

Требуют включённых demo auth и свободных профилей; читают секреты из локального env. Reservations делает два параллельных HTTP запроса, проверяет201/409/replay и отменяет **свою** созданную бронь. Trips проходит start/pause/resume/finish/declined/approved/replay через frontend proxy. Realtime подключает три WS, проверяет движение/расход/disconnect/recovery и одно локальное письмо. Поездки/счета остаются в истории; scripts не являются тестами, очищающими main. Истинная конкуренция PG-barrier доказывается integration, двух браузеров — Playwright.

## Независимый чистый стенд

Для повторения без использования существующего volume возьмите отдельную копию исходников без .env/node_modules/dist и выполните npm ci/setup. В её .env задайте новый COMPOSE_PROJECT_NAME, свободные WEB_PORT/API_PORT/POSTGRES_PORT и согласуйте DATABASE_URL/VITE_PROXY_TARGET/WS_ALLOWED_ORIGINS. Не печатайте готовый DATABASE_URL или docker compose config без --quiet. `COMPOSE_PROJECT_NAME` меняет namespace контейнеров/volume, порты сами не меняются.

Для U021 проверена отдельная копия HEAD b7a6c75 с новым volume, ports5190/3190/54339 и случайными заново созданными credentials. Docker layer cache был доступен; это не заявление о запуске на машине без Docker/npm cache. После проверки удаляется только явно названный проверочный Compose project/volume, основной samokettik сохраняется.
